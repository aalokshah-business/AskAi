description: Open the AskAI terminal. AI setup and review run only when explicitly requested with --review.
---

Run `askai cli --prepare --json`. Default: open the terminal only. Add `--review` ONLY when the user explicitly requests AI analysis, review, or AI-generated project guidance. Do not infer consent from source changes or a stale pack. If the user named a project or folder, add `--project` or `--path`. During explicit review, pass their description with `--about "their words"`; add `--refresh` for requested setup refresh and `--offline` only when requested or the network is unavailable. `--refresh` alone does not enable review.

Prepare finds the project itself: the named path, otherwise the repository or manifest folder of this chat, otherwise the only registered project. If the JSON has `need` `project`, ask that one `question` and run prepare again with the answer as `--path` or `--project`. If `need` is `about`, ask that question, show `default`, and run prepare again with `--about`. Accept a dictated answer. AskAI cannot open a microphone. If they accept the default, pass that text as `--about`. Do not continue while prepare exits 2. Never initialize an unrelated folder.

If `action` is `launch`, open the terminal in the returned project folder and stop. Do not scan files, call infra or todo, ask for a description, run init, research, or mark review done. `review.skipped` means review was not checked; never describe that as current or verified. If `setup` is `not-initialized`, mention that `askai init` can initialize the project in the terminal. A normal launch still works.

Only during explicit `--review`: on a machine with no recorded AskAI installation profile, prepare installs `max` for the recorded target before init. Existing recorded profiles are kept; `--refresh` reruns setup. Normal launch never installs tools. Use `askai install` to change tools. Healthy components are skipped. A download failure does not invalidate a review. uv can use PyPI when `astral.sh` is blocked. Context Mode requires Node 22.5; RTK requires Rust or Homebrew. Claude LSP installs only for a selected Claude Code target.

Only if the user explicitly requested review and `action` is `review`, prepare already ran `askai init --path <project-folder> --yes` when the pack was missing or source had changed (scan, official docs, project files). Then:
1. For a new project, inspect the small router and map, then search `docs/ai/SOURCE_INDEX.md` for relevant paths; do not load the whole index into the chat. For a stale project, begin with `review.changed`, `review.removed`, and `review.missing` from prepare, then inspect affected documentation and code. If `review.pathsTruncated` is true, get the full path list with `askai review status --project <name> --all --json` before marking review done. Check static conclusions against source and tests. Research the detected stack in official docs when web tools exist. Do not send private source to web services.
2. Fill evidence-backed gaps in `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorignore`, `docs/ai/PROJECT_MAP.md`, `ARCHITECTURE.md`, `FEATURES.md`, `MODELS.md`, and the generated agent files and skills. Keep always-loaded instructions short. Preserve user edits. Put the current goal in `WORK_ORDER.md` only if this chat established it. Write `HANDOFF.md` only from actual session progress. Do not invent decisions, security invariants, or feature completion.
3. Ask one bundled question only for `questions` that code and this chat still cannot answer. Run `askai infra --project <name>` and `askai todo --project <name>`. Record `askai review done --project <name>` only after the review. Report remaining evidence gaps.

Then run `askai cli --launch`. A devcontainer has no display, so this does not open a new window. If the output says `tmux attach -t askai` or `screen -r askai`, that session is the CLI: tell the user to run that command in the Cursor terminal. If it says it is starting in this terminal, that terminal is the CLI. If tmux is missing, tell the user to run `askai cli` in the Cursor terminal. On Windows desktop, `askai cli --launch` spawns the AskAI CLI console window automatically. Also inform Cursor and Antigravity users they can open the integrated CLI directly via Terminal -> Run Task -> "AskAI CLI" or through the "AskAI CLI" terminal profile without running shell commands. `askai upgrade` and `askai setup` install tmux on a headless machine when they can do it without a password. None of these is a failed review. Tell the user which project was selected. AI review uses model tokens only when explicitly requested. Commands in the terminal use none unless they launch an AI agent.
